
《数据库智能助手（ChatDB Agent）》产品需求文档 (PRD)

1. 文档概述
   1.1 产品背景
   在日常研发与DBA运维过程中，存在SQL编写效率低、表结构设计不规范、慢查询与故障排查门槛高、知识分散难以沉淀等痛点。本产品旨在通过大语言模型（LLM）与Agent技术，打造一站式的对话式数据库智能助手，降低数据库使用门槛，提升研发与运维效率。

1.2 产品目标
提供知识问答、SQL编码、设计辅助、故障排查等一站式服务，实现“自然语言即代码、即洞察”。

2. 用户角色与使用场景
   后端研发工程师：快速生成符合业务逻辑的SQL，获取表结构与索引设计的规范建议，获取常见报错的处理方案。

数据库管理员 (DBA)：利用AI辅助进行慢SQL诊断、AWR报告解析、系统突发CPU飙高的快速归因分析。

数据分析师：通过自然语言直接查询取数，检索指标口径与数据库知识。

3. 产品核心流程
   用户创建/进入历史会话，输入自然语言或上传附件（≤10MB）。

系统进行意图识别与路由（规则+LLM双轨路由）。

分发至特定领域的专家Agent。

Agent调用底层工具（RAG知识检索、只读SQL执行器、元数据查询等）执行任务。

结果以流式（SSE）形式返回前端展示（包含思考过程摘要、最终结果）。

全过程沉淀至会话历史，用于多轮对话与审计。

4. 详细功能需求
   4.1 全局框架与交互模块
   侧边栏（会话管理）：

支持“新建会话”。

历史会话按时间维度自动分组（今天、近7天、近30天、更早），支持点击恢复上下文。

主界面输入区：

支持多行文本输入，支持Shift+Enter换行，Enter发送。

提供快捷提问示例提示（如：“帮我写一条查询最近7天各部门销售额的SQL”）。

附件上传：支持拖拽/点击上传图片、文档（最大10MB），用于解析ER图、上传错误日志、AWR报告等。

结果展示区：

支持Markdown渲染（代码高亮、表格）。

支持“思考过程”折叠展示（如：展示Agent调用了哪些工具、检索了哪些规范）。

4.2 核心功能一：SQL编码与优化 Agent
自然语言转SQL (Text2SQL)：结合业务术语库与数据库Schema，将自然语言准确转换为可执行SQL。

DDL生成：根据业务需求生成符合命名规范的建表语句。

精准识别与纠错：识别用户输入SQL的语法/语义错误，并给出修正后的版本。

优化建议：对已有SQL给出重写建议，提升执行效率。

4.3 核心功能二：表结构与索引设计 Agent
现状读取：能够主动调取并分析当前数据库的表结构、现有索引信息（需用户提供目标库信息）。

规范校验：依托内置的数据库设计规范（如三范式、字段类型长度约束），智能评估用户提供的表结构/索引设计的优劣，并给出修改意见。

4.4 核心功能三：故障诊断 Agent
慢SQL诊断：结合执行计划（Explain）和表统计信息，分析慢SQL根因（如全表扫描、索引失效）。

AWR报告分析：解析上传的AWR报告或日志文件，对比双报差异，定位性能瓶颈。

瞬时飙高定位：结合历史监控数据或SQL审计日志，分析CPU突增的“罪魁祸首”。

4.5 核心功能四：数据库知识与案例 Agent
知识问答：基于RAG检索官方文档、内部Wiki，回答数据库规范、索引原理等纯知识类问题（回答需附带引用来源）。

案例复盘：提供典型故障、经典优化的案例库检索。

转型指导：提供不同数据库（如Oracle转PostgreSQL）的语法转换、特性适配指导。

5. 技术架构映射 (基于Python落地)
   为了支撑上述需求，底层必须采用解耦架构：

接入层：FastAPI 提供RESTful API与SSE流式响应，处理大文件临时存储与鉴权。

路由与编排层：LangGraph 构建状态机。Phase 1 使用关键词/正则做快速确定性路由（如包含“AWR”直接进诊断Agent）；Phase 2 使用轻量LLM进行意图分类与参数抽取。

Agent执行层：LangChain构建ReAct Agent，封装各类Tool。

数据与存储层：

结构化元数据/长期记忆：PostgreSQL。

向量知识库：pgvector 存储业务术语、设计规范、文档切片。

短期记忆/会话状态：Redis 缓存当前多轮对话上下文。

大模型底座：兼容OpenAI接口的各家LLM（如GPT-4、通义千问等），支持按任务复杂度动态路由模型。

工具集：SQLAlchemy（异步只读执行）、文件解析器（PDF/Word/图片OCR）。

6. 非功能性需求（重点：安全与体验）
   6.1 安全控制（红线要求）
   只读隔离：执行Text2SQL所连接的数据库账号必须是只读账号。

SQL拦截防护：在执行前，通过词法分析拦截 INSERT、UPDATE、DELETE、DROP 等写操作或高危操作。

多租户隔离：用户只能访问授权的数据库Schema，向量库检索按租户/项目空间隔离。

审计追溯：100%记录用户的提问、模型生成的SQL、真实执行结果，满足安全合规。

6.2 性能与体验
流式输出：大模型生成过程和工具执行过程需通过 SSE 推送到前端，降低用户等待焦虑。

超时与熔断：数据库查询强制设置超时阈值（如10秒），LLM生成设置重试上限，超时降级为提示信息。

上下文管理：长对话自动进行历史摘要压缩，防止Token溢出。

7. 产品迭代规划建议
   V1.0（MVP期）：上线“会话管理 + 知识问答Agent + SQL编码Agent”。跑通“文档入库-RAG检索-流式输出”主链路，支持基础的Text2SQL。

V2.0（工具拓展期）：引入“表结构设计Agent”与“故障诊断Agent”。重点打磨底层Tool的稳定性与安全拦截机制，支持附件解析（日志/AWR）。

V3.0（体验与闭环）：引入用户反馈机制（点赞/点踩/SQL纠错回流），优化路由准确率；支持将生成的优质SQL沉淀入专属语料库；完成多租户权限的深度控制。
